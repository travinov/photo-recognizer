# Photo Recognizer

Web-приложение для поиска людей на фотографиях конференции.

Проект индексирует изображения, находит на них лица, присваивает каждому распознанному лицу сквозной уникальный номер в базе и позволяет:

- искать похожие лица по загруженной фотографии;
- искать похожие лица по `ID лица`;
- открывать любую фотографию и видеть рамки найденных лиц;
- просматривать результаты поиска с совпадениями по базе;
- листать весь каталог фотографий по страницам.

## Что реализовано

- индексатор фотографий в SQLite;
- детекция нескольких лиц на одном фото;
- сквозная нумерация лиц в базе вида `Лицо 1`, `Лицо 2`, `Лицо 292`;
- поиск похожих лиц по face embedding;
- поиск по уже известному `ID лица`;
- Web UI для просмотра фотографий, лиц и совпадений;
- пагинация каталога фотографий.

## Техническое описание

### Стек

- `FastAPI` для HTTP и Web UI;
- `Jinja2` для серверных HTML-шаблонов;
- `face_recognition` + `dlib` для детекции лиц и расчета embeddings;
- `SQLite` для хранения индекса;
- `Pillow` и `numpy` для работы с изображениями и векторами.

### Архитектура

Проект собран как простой монолит с разделением на слои:

- [main.py](main.py): точка входа приложения;
- [photo_recognizer/web.py](photo_recognizer/web.py): HTTP-маршруты, пагинация, рендеринг HTML;
- [photo_recognizer/services.py](photo_recognizer/services.py): индексация и поиск;
- [photo_recognizer/db.py](photo_recognizer/db.py): работа с SQLite;
- [photo_recognizer/face_engine.py](photo_recognizer/face_engine.py): детекция лиц и расчёт embeddings;
- [templates/](templates): HTML-шаблоны интерфейса;
- [static/styles.css](static/styles.css): стили интерфейса.

### Модель данных

Используются две основные таблицы:

- `photos`: информация о фотографии;
- `faces`: найденные лица на фото, координаты рамки, embedding и кроп лица.

Связь `photos -> faces` это `one-to-many`, поэтому одна фотография может быть связана с несколькими людьми.

### Как работает поиск

1. Индексатор проходит по каталогу фотографий.
2. Для каждого изображения находятся лица.
3. Для каждого лица вычисляется embedding.
4. Координаты лица, embedding и кроп сохраняются в SQLite и `data/`.
5. При поиске загруженная фотография или лицо из базы преобразуется в embedding.
6. Дальше выполняется сравнение с embeddings из базы через расстояние между векторами.
7. Возвращаются самые близкие совпадения.

### Нумерация лиц

Локальная нумерация вида `Человек 1` внутри одного кадра больше не используется как основной идентификатор.

Сейчас отображается сквозной уникальный номер лица из базы:

- `Лицо 1`
- `Лицо 2`
- `Лицо 292`

Для временных лиц на только что загруженной фотографии используются обозначения:

- `Запрос 1`
- `Запрос 2`

### Ограничения текущего решения

- используется CPU-режим `hog`, поэтому индексация не мгновенная;
- качество поиска зависит от качества исходных фотографий;
- это поиск похожих лиц, а не полноценная identity-resolution система;
- один и тот же человек на разных фотографиях пока не объединяется в отдельную сущность `Person`.

## Установка

```bash
python3.12 -m venv .venv
source .venv/bin/activate
CMAKE_GENERATOR=Ninja pip install -r requirements.txt
```

Почему именно так:

- для `face_recognition` нужен `dlib`;
- в этом окружении `dlib` стабильнее собирается через `Ninja`;
- в `requirements.txt` зафиксирован `setuptools<81`, потому что `face_recognition_models` использует `pkg_resources`.

Если установка `dlib` всё равно падает, проверьте наличие:

- `cmake`
- `ninja`
- Xcode Command Line Tools

## Данные

По умолчанию изображения читаются из папки `tcf/`.

Переопределение пути:

```bash
export PHOTO_RECOGNIZER_IMAGES_DIR="/absolute/path/to/photos"
```

## Индексация

```bash
python -m photo_recognizer.cli index
```

После индексации:

- база сохраняется в `data/face_index.db`;
- кропы лиц сохраняются в `data/face_crops/`;
- загруженные поисковые изображения сохраняются в `data/query_uploads/`.

## Запуск Web UI

```bash
uvicorn main:app --host 127.0.0.1 --port 8000
```

После запуска откройте:

```text
http://127.0.0.1:8000
```
